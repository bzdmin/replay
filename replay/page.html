Replay

Rehearse a change before you ship it.
Replay runs the same scenarios against your current and your proposed behaviour, compares what actually happened, then has a verifier challenge the result. Built with the Strands Agents SDK on Amazon Bedrock.
What a rehearsal finds
Transaction fee 2.5% → 2%, one line, one file
↓
✓ Payment path changed, exactly as intended
⚠ Refund path changed too, and a contract fixes it at 2.5%
⚠ Legacy billing never changed, though the same rule governs it
↓
Two contract violations, in opposite directions. Neither appears in the diff. Neither throws an error.
Takes about two minutes.
What is it rehearsing against? A small payments application called AcmePay, included in this project at demo-repo/acmepay. It has a payment service, a refund service, a modern billing service, a legacy billing engine ported from a mainframe, and a written rulebook of contractual business rules. Replay reads it, runs it, changes it, and runs it again. Browse it before you start and the findings below will mean more.

Where Replay works

It needs three things, and it is honest about all of them.

  • ✓ Behaviour it can execute - functions that take inputs and return values.
  • ✓ Intent written down - a rulebook, a spec, documented policy. Without it there is nothing to predict against, only code to describe.
  • ✓ Reachable in a single call - pricing, fees, billing, tax, policy engines.
  • ✗ Not yet: behaviour that needs setup first. A login flow or a shopping cart has memory, and Replay does not generate the steps to put it in the right state.

Pointed at a codebase it cannot handle, it discards the scenarios it could not run and says so, rather than inventing findings.

Run it on your own code

This page only rehearses against the bundled demo application, on purpose: Replay executes the code it is given, so a public box accepting any repository would be executing strangers' code on this server.

git clone https://github.com/bzdmin/replay
cd replay
pip install -r requirements.txt

python scripts/check_aws.py

python scripts/rehearse.py \
  --repo /path/to/your/project \
  "Change the retry limit from 3 to 5"

You bring your own AWS credentials, and it runs entirely on your machine.

What's next

  • Scenarios with setup. Multi-step scenarios in a locked-down sandbox, so stateful behaviour becomes reachable. The sandbox is the hard part, not the scenarios.
  • Beyond code. Configuration, dependency upgrades and schema migrations are changes too, and they break the same rules.
  • Behavioural equivalence. Does a rewritten service still preserve the behaviour that mattered? That is the same question asked of a migration.
  • Run it on a pull request. A rehearsal is most useful before review, not after.
